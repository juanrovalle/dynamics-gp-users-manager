Dynamics GP UserOps
Windows Server installation

Administration with Desktop Experience, local or remote SQL, and RDP operation.

The same Setup.exe targets Windows 11 x64 and Windows Server 2016, 2019, 2022 and 2025 x64 with Desktop Experience. Version 4.0.0 uses SQL schema 4. These are installation targets, not completed certification on actual servers; record acceptance results for the customer's exact Windows, SQL and GP builds.

1. Choose the administration host

Install the console on an administration server with a graphical desktop, or on a separate Windows 11 workstation. The SQL Server machine may host it, but that is not required.

Do not install this graphical console on Server Core or Nano Server. Setup rejects those installation types. If SQL/GP is hosted on a headless server, use another supported administration computer and independently validate server-side SQL/GP compatibility.

Do not change server roles, add IIS, enable RDP or expose SQL ports simply to install the console. IT must approve infrastructure changes separately. Installing the console on a domain controller is not recommended; detecting a server product type is not an architectural recommendation.

2. Check prerequisites

Run these read-only checks in PowerShell on the intended administration computer:

Get-CimInstance Win32_OperatingSystem |
    Select-Object Caption, Version, BuildNumber, OSArchitecture, ProductType
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' |
    Select-Object InstallationType

InstallationType must be Server, not Server Core or Nano Server. Setup accepts LTSC build families 14393 (2016), 17763 (2019), 20348 (2022) and 26100 (2025). Monthly revisions within these families do not require another installer.

Prepare an existing SQL Server with Agent, the GP system database and the separate manager database name. Keep Windows, SQL and GP within the customer's supported lifecycle and patch policy. Runtime support alone does not certify GP.

Prepare the account responsibilities described in the main guide: Windows installer elevation, SQL installation administration, daily product operation, and restricted engine identity plus explicitly selected Agent owner. No SQL passwords are passed to Setup.

3. Install the Windows files

  1. Copy Setup.exe and compare its SHA-256 with the supplied checksum.
  2. Sign in locally or through an authorized RDP desktop session.
  3. Run Setup as a Windows administrator, review the license and install.
  4. Open Dynamics GP UserOps from Start.
  5. Follow the English-language six-step SQL wizard in the installation and testing guide.

The package includes the .NET Desktop Runtime. No SDK, sqlcmd, ASP.NET Hosting Bundle or IIS is needed. Installation does not download dependencies.

Optional unattended file installation

Use an elevated PowerShell session. This installs Windows files only:

# Work in the folder containing Setup.exe.
New-Item -ItemType Directory -Path 'C:\Temp\UserOps' -Force | Out-Null
$setupProcess = Start-Process -FilePath '.\Setup.exe' `
    -ArgumentList '/VERYSILENT', '/SUPPRESSMSGBOXES', '/NORESTART', '/LOG="C:\Temp\UserOps\setup.log"' `
    -WindowStyle Hidden -Wait -PassThru
if ($setupProcess.ExitCode -ne 0) {
    throw "Setup requires attention; exit code $($setupProcess.ExitCode). Inspect C:\Temp\UserOps\setup.log."
}
This does not silently install SQL objects, grant SQL permissions or enable removals. Open the console and complete the wizard afterward. The generated delivery is unsigned; apply the customer's software-origin policy and use the signing option in build.ps1 when a certificate is available.

4. Connect to SQL

For local SQL use the actual server/instance name, such as SRV-GP or SRV-GP\GPINSTANCE. For remote SQL, use the approved host/instance or host,port. Windows local administrator rights do not automatically grant SQL administrator rights.

Retain encrypted SQL connections. IT should verify the certificate, endpoint and authentication before making security changes.

For a known fixed TCP port, IT may test connectivity without changing firewall rules:

# Replace the endpoint and port with those assigned by the DBA.
Test-NetConnection -ComputerName 'SRV-SQL' -Port 1433

Named instances may use another port. A successful TCP check is not a successful SQL login or proof of GP permissions.

5. Verify server operation

Run the full acceptance checklist, then additionally:

  • Test the intended local/remote SQL connection and both authorized authentication modes.
  • Confirm installation starts on the selected Desktop Experience host and is rejected on Core/Nano before application files are installed.
  • Check that another RDP user's connection profile is separate and contains no password.
  • Close the console and sign out of RDP. Observe from another authorized computer that SQL Agent continues enforcing quotas.
  • Pause automation and confirm a subsequent PAUSED execution. Pause applies to the managed database globally, not just the current RDP user.
  • Restart SQL/Agent in the isolated test environment, prepare the GP/Dexterity tables through the GP client and verify job recovery.
  • Validate native messages in the actual GP client. Running the console on Server is not evidence that a GP user saw a message.

The product does not add a Windows service or a Windows Task Scheduler task. SQL Server Agent remains the engine. No interactive account must stay signed in to keep it running.

6. Upgrade or uninstall

To upgrade from GP Users Manager 3.x, close the old console and run Dynamics GP UserOps 4.0.0 Setup interactively. Setup detects the legacy AppId, removes only the old Windows console, and keeps the SQL database and Agent jobs running. First launch copies the password-free profile to the new LocalAppData folder while retaining the original. Select the existing manager database and job; do not create replacements.

Schema migration 4 updates branded metadata and the test-message procedure. It preserves quota policies and the compatible gpManager* / SP_GPUM_* SQL contract.

When upgrading from the original SQL-only schema, follow the full SQL upgrade wizard. Do not create a new manager database in place of upgrading the existing one.

Uninstall removes the console, not SQL databases or the job. To stop automation, pause it and verify PAUSED before the DBA disables the job and Windows uninstalls the console.
