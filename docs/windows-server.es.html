GUÍA DE SERVIDOR · VERSIÓN 4.0.0

Dynamics GP UserOps
Instalación en Windows Server

Administración con Desktop Experience, SQL local o remoto y operación mediante RDP.

Guías / GuidesEspañolEnglishInstalación y pruebas

El mismo Setup.exe está preparado para Windows 11 x64 y Windows Server 2016, 2019, 2022 y 2025 x64 con Desktop Experience. La versión 4.0.0 usa el esquema SQL 4. Son destinos de instalación, no una certificación completada en servidores reales; registra la aceptación para los builds exactos de Windows, SQL y GP del cliente.

1. Elegir equipo2. Revisar requisitos3. Instalar4. Conectar a SQL5. Verificar6. Actualizar / desinstalar

1. Elegir el equipo de administración

Instala la consola en un servidor administrativo con escritorio gráfico o en un equipo Windows 11 separado. Puede estar en el equipo de SQL Server, pero no es obligatorio.

No instales esta consola gráfica en Server Core ni Nano Server. Setup rechaza esos tipos de instalación. Si SQL/GP está en un servidor sin escritorio, utiliza otro equipo de administración admitido y valida por separado la compatibilidad de SQL/GP del servidor.

No cambies roles del servidor, agregues IIS, habilites RDP ni expongas puertos SQL solo para instalar la consola. TI debe aprobar por separado los cambios de infraestructura. No se recomienda instalar la consola en un controlador de dominio; detectar un tipo de producto servidor no equivale a recomendar esa arquitectura.

2. Revisar los requisitos

Ejecuta estas consultas de solo lectura en PowerShell, en el equipo que administrará el producto:

Get-CimInstance Win32_OperatingSystem |
    Select-Object Caption, Version, BuildNumber, OSArchitecture, ProductType
Get-ItemProperty 'HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion' |
    Select-Object InstallationType

InstallationType debe ser Server, no Server Core ni Nano Server. Setup admite las familias de builds LTSC 14393 (2016), 17763 (2019), 20348 (2022) y 26100 (2025). Las revisiones mensuales de esas familias no requieren otro instalador.

Prepara un SQL Server existente con Agent, la base de sistema GP y el nombre de la base separada del gestor. Mantén Windows, SQL y GP dentro del ciclo de soporte y la política de actualizaciones del cliente. El soporte del runtime por sí solo no certifica GP.

Prepara las responsabilidades de cuentas de la guía principal: elevación para instalar archivos Windows, administración de instalación SQL, operación diaria del producto e identidad restringida del motor con propietario de Agent elegido explícitamente. Setup no recibe contraseñas SQL.

3. Instalar los archivos de Windows

  1. Copia Setup.exe y compara su SHA-256 con la huella entregada.
  2. Inicia sesión localmente o mediante una sesión de escritorio RDP autorizada.
  3. Ejecuta Setup como administrador de Windows, revisa la licencia e instala.
  4. Abre Dynamics GP UserOps desde Inicio.
  5. Completa los seis pasos del asistente SQL en la guía de instalación y pruebas. La aplicación muestra sus controles en inglés y la guía indica los nombres exactos.

El paquete incluye .NET Desktop Runtime. No necesitas SDK, sqlcmd, ASP.NET Hosting Bundle ni IIS. La instalación no descarga dependencias.

Instalación desatendida opcional de archivos

Utiliza una sesión PowerShell elevada. Esto instala únicamente los archivos Windows:

# Trabaja en la carpeta que contiene Setup.exe.
New-Item -ItemType Directory -Path 'C:\Temp\UserOps' -Force | Out-Null
$setupProcess = Start-Process -FilePath '.\Setup.exe' `
    -ArgumentList '/VERYSILENT', '/SUPPRESSMSGBOXES', '/NORESTART', '/LOG="C:\Temp\UserOps\setup.log"' `
    -WindowStyle Hidden -Wait -PassThru
if ($setupProcess.ExitCode -ne 0) {
    throw "Setup requiere atención; código $($setupProcess.ExitCode). Revisa C:\Temp\UserOps\setup.log."
}
Esto no instala objetos SQL, concede permisos SQL ni activa retiros de forma silenciosa. Abre la consola y completa después el asistente. La entrega generada no tiene firma digital; aplica la política del cliente para verificar su origen y utiliza la opción de firma de build.ps1 cuando dispongas de un certificado.

4. Conectar a SQL

Para SQL local utiliza el nombre real del servidor/instancia, como SRV-GP o SRV-GP\GPINSTANCE. Para SQL remoto usa el servidor/instancia o servidor,puerto aprobado. Ser administrador local de Windows no otorga automáticamente administración de SQL.

Mantén las conexiones SQL cifradas. TI debe revisar certificado, punto de conexión y autenticación antes de hacer cambios de seguridad.

Para un puerto TCP fijo conocido, TI puede comprobar conectividad sin modificar el firewall:

# Sustituye el equipo y puerto por los asignados por el DBA.
Test-NetConnection -ComputerName 'SRV-SQL' -Port 1433

Una instancia con nombre puede usar otro puerto. Una prueba TCP correcta no equivale a un inicio de sesión SQL correcto ni demuestra permisos en GP.

5. Verificar la operación en el servidor

Ejecuta la lista completa de aceptación y, además:

  • Prueba la conexión SQL local/remota prevista y ambos modos de autenticación autorizados.
  • Comprueba que la instalación inicia en el equipo con Desktop Experience y se rechaza en Core/Nano antes de instalar archivos de la aplicación.
  • Verifica que el perfil de conexión de otro usuario RDP sea separado y no contenga contraseña.
  • Cierra la consola y termina la sesión RDP. Observa desde otro equipo autorizado que SQL Agent continúa aplicando los cupos.
  • Pausa la automatización y confirma una ejecución posterior PAUSED. La pausa afecta globalmente a la base administrada, no solo al usuario RDP actual.
  • Reinicia SQL/Agent en el entorno aislado, prepara las tablas GP/Dexterity mediante el cliente GP y verifica que el job se recupere.
  • Valida los avisos nativos en el cliente GP real. Ejecutar la consola en Server no demuestra que un usuario GP vio un mensaje.

El producto no agrega un servicio Windows ni una tarea en el Programador de tareas de Windows. SQL Server Agent sigue siendo el motor. No es necesario mantener una cuenta interactiva conectada para que funcione.

6. Actualizar o desinstalar

Para actualizar desde GP Users Manager 3.x, cierra la consola anterior y ejecuta Dynamics GP UserOps 4.0.0 Setup de forma interactiva. Setup detecta el AppId anterior, retira solo la consola Windows y conserva en ejecución la base SQL y los jobs de Agent. El primer inicio copia el perfil sin contraseña a la nueva carpeta LocalAppData y conserva el original. Selecciona la base y el job existentes; no crees reemplazos.

La migración 4 actualiza metadatos de marca y el procedimiento del mensaje de prueba. Conserva las políticas de cupo y el contrato SQL compatible gpManager* / SP_GPUM_*.

Si actualizas desde el esquema original de solo SQL, sigue el asistente completo de actualización SQL. No crees una base del gestor nueva en lugar de actualizar la existente.

Desinstalar elimina la consola, no las bases SQL ni el job. Para detener la automatización, pausa y verifica PAUSED antes de que el DBA deshabilite el job y se desinstale la consola en Windows.
